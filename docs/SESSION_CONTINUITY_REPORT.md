# Session Continuity Report

## 현재 판정

**PASS — 실제 두 계정 사이에서 동일 task 재개와 후속 코드 작업 성공**

계정 A에서 시작한 기존 Codex task를 계정 B로 전환한 뒤 다시 열었고, 이전 대화에서 결정한 구현 내용과 오류 원인을 새로 설명하지 않고 이어받았습니다. 이어서 실제 소스 수정, 자동 테스트, Release 빌드와 앱 재설치까지 완료했습니다.

이 판정은 저장된 대화·세션·프로젝트 맥락의 실용적 연속성을 뜻합니다. 이전 모델의 순간적인 비공개 추론 상태가 다른 계정이나 모델에 그대로 복제된다는 의미는 아닙니다.

## 공개 검증 환경

| 항목 | 값 |
|---|---|
| 운영체제 | macOS, Apple Silicon |
| 공식 앱 | ChatGPT/Codex 데스크톱 앱, Bundle ID `com.openai.codex` |
| 인증 저장 방식 | 공유 `~/.codex/auth.json`, 권한 `0600`, App Server `type=chatgpt` 확인 |
| 계정 | 사용자가 소유한 ChatGPT 계정 A와 B |
| 프로젝트 | 두 계정 모두 동일한 로컬 작업 폴더 사용 |

개인 이메일, thread/session ID, 계정별 사용량과 로컬 파일 개수는 공개 보고서에 기록하지 않습니다.

## 확인한 것

- 계정 A와 B 프로필을 각각 공식 로그인 흐름으로 등록
- Switcher 메뉴에서 사용자 승인형 A→B 인증 전환 성공
- standalone Codex CLI 감지와 승인 후 정상 종료 성공
- 공식 앱 정상 종료와 원래 설치 경로 재실행 성공
- 전환 전과 같은 task가 목록에 유지되고 다시 열림
- 이전 대화의 구체적인 오류 원인, 설계 결정과 검증 결과를 새 계정에서 회상
- 같은 task에서 실제 후속 소스 수정 수행
- 후속 자동 테스트 24개 통과, Release 빌드·설치 성공
- 세션·프로젝트 파일 손상 또는 새 task 강제 분기 없음

## 판정 기준

- **PASS**: 대상 계정 전환이 확인되고 같은 task에서 과거 맥락 회상과 실제 후속 작업이 성공함
- **PARTIAL**: 로컬 파일과 세션 목록은 유지되지만 후속 실행이 거부되거나 새 task로 분기함
- **FAIL**: 계정 변경 후 기존 세션이 사라지거나 열리지 않음

## 재현 절차

1. Release 앱에서 현재 계정 A를 등록합니다.
2. `계정 추가` 또는 `Device Code 추가`로 계정 B를 등록합니다.
3. 기존 task에서 구체적인 마커나 작업 결정을 기록합니다.
4. 실행 중인 별도 CLI가 있으면 Switcher의 목록을 확인하고 `CLI 종료 후 전환`을 승인합니다.
5. B로 전환한 뒤 공식 앱에서 같은 task를 엽니다.
6. 이전 마커나 결정의 회상을 요청하고 작은 실제 후속 작업을 실행합니다.
7. 현재 계정 표시, 작업 결과와 보호 파일 상태를 확인합니다.
8. 필요하면 A로 다시 전환해 동일 task가 계속 열리는지 확인합니다.

세션 파일이 존재한다는 사실만으로 PASS 처리하지 않습니다. 대상 계정에서 같은 task의 실제 후속 요청이 성공해야 합니다.

## 실패 시 복구

보호 파일 삭제나 대상 계정 검증 실패가 발생하면 Switcher는 이전 인증으로 자동 롤백합니다. 수동 복구가 필요하면 공식 앱을 종료한 뒤 다음을 실행합니다.

```bash
./scripts/emergency-restore.sh
```

인증 원문과 브라우저 로그인 URL은 보고서와 로그에 기록하지 않습니다.
